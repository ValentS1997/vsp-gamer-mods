# PlanBuild — подготовка перестройки дома (выбран 24.10.2026)

**Решение пользователя:** включить [PlanBuild **0.20.0**](https://thunderstore.io/c/valheim/p/MathiasDecrock/PlanBuild/v/0.20.0/) в модпак VSP Gamer: существующий дом трудно перестроить из-за большого числа полных сундуков. Отдельный кандидат **ChestSizeConfig** пока не выбран, не учитывать как установленную DLL.

## Статус включения

- **Выбранный мод:** PlanBuild 0.20.0, ожидаемый файл **`PlanBuild.dll`** (подтверждён `<AssemblyName>PlanBuild</AssemblyName>` в upstream `PlanBuild/PlanBuild.csproj`).
- **Политика сборки:** **Server / Client** — установить на P2P-хосте и двух клиентах ради единого набора возможностей и модовых объектов. Автор допускает подключение клиента без PlanBuild к серверу с PlanBuild, но такой клиент не увидит запланированные детали. Клиент **с** PlanBuild не может подключиться к хосту **без** PlanBuild. Поэтому синхронизировать установку, прежде чем играть вместе.
- **Зависимости 0.20.0:** `BepInExPack_Valheim >=5.4.2350` и `Jotunn >=2.30.1` — обе уже присутствуют как отдельные зависимости сборки, **новых зависимых DLL не прибавлять**; точные локальные версии перепроверить. **HookGenPatcher НЕ нужен** начиная с PlanBuild 0.19.0.
- **Текущее число выбранных активных DLL:** 47 S/C + 10 Only Client = **57**; намеренно выключенный `DigDug.dll*` отдельно, итого 58 учтённых.
- **Установка, DLL-файл, CFG и работа на локальных игровых ПК не подтверждены.** Решение и манифест обновлены **только в Git**; по этому распоряжению **CFG не создавался**.

## Важный сценарий: перестройка с заполненными сундуками

PlanBuild умеет сохранить структуру дома и содержимое контейнеров в `.blueprint`. Начиная с версии **0.19.1** исправлен захват/восстановление инвентаря для Valheim 1.0, а версия **0.20.0** включает это исправление. По исходникам:
- `PlanBuild/Blueprints/Blueprint.cs` записывает данные инвентаря контейнера (`ZDO: ZDOVars.s_items`) в поле дополнительной информации записи чертежа.
- `PlanBuild/Blueprints/Components/PlacementComponent.cs` восстанавливает `ZDOVars.s_items` **только при `placeDirect=true`**, то есть в **Direct Build**, а не в обычном **Plan** режиме.
- **Save** сохраняет постоянный `.blueprint` на диск. **Copy** сохраняет лишь временную запись Clipboard до выхода из мира. **Cut** удаляет выбранные оригинальные строительные детали **без компенсации материалов**; не использовать для основной базы до проверки восстановления.
- **Direct Build** возводит детали без строительных материалов, по умолчанию запрещён обычным участникам, но доступен администратору. При неразрушенном старом доме даёт **дубликаты сундуков и предметов**, а не перемещение с вычетом из оригинала; возможны и другие последствия при повреждённой или частично несовместимой схеме.

### Минимальный безопасный тест и перестройка

1. Остановить игру; **сохранить мир и персонажей** вне их игровых каталогов. При необходимости скопировать также будущие `.blueprint` файлы.
2. На копии мира либо в безопасном месте протестировать **один небольшой домик с одним непустым сундуком**: сохранить как `.blueprint` через **Save**, проверить восстановление в режиме **Direct Build**, сопоставить предметы и их количества.
3. Сохранить полный исходный дом отдельным именем **до** его разбора. Сделать ещё одну копию файла `.blueprint` за пределами каталога игры.
4. Для перестройки без бесплатного дублирования использовать обычный **Plan** режим для дома и **реально перенести имущество** в временный склад (хотя это потребует перекладывания вещей).
5. Альтернатива, если допустимо фактически копировать полные сундуки: после **обязательного теста**, Direct Build воспроизводит **снимок содержимого**. Старые сундуки сами не очистятся; не пользоваться обеими копиями одновременно, иначе можно непреднамеренно дублировать ценную добычу. Перемещение нужно контролировать вручную.
6. До финального удаления оригинального склада убедиться, что **модовые предметы, контейнеры и строительные детали** действительно восстановились, особенно объекты из других модов. Сохранение не заменяет резервную копию мира.

### Контроли и совместимость

- Выбор фрагментов с **Blueprint Rune**, затем действие **Save** (не Copy и не Cut). Файлы проекта по умолчанию находятся в `BepInEx/config/PlanBuild/blueprints`.
- При размещении схемы переключение в **Direct Build** по умолчанию с помощью **Ctrl**; администраторы имеют право на такой режим без включения общего разрешения `Allow direct build`.
- Совместимость с **AzuCraftyBoxes** заявлена автором; пересечение с уже выбранным **Quads Build Orders** пока не проверялось. Не применять обе системы к одной основе в одном тесте, пока не подтверждена совместимость.
- Установка у всех трех игроков разумна из-за разных функций и создаваемых объектов. Весь пакет PlanBuild устанавливается в `BepInEx/plugins/PlanBuild`, зависимые BepInEx и Jötunn уже входят в набор.
