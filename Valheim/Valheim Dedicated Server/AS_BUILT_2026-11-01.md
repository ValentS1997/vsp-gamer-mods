# VSP Gamer — Valheim Dedicated Server: as-built и история развёртывания

**Снимок:** 2026-11-01 · **Контур:** тестовый забег на выделенном сервере · **Статус:** публичный игровой доступ подтверждён владельцем; production/security acceptance не завершён.  
**Проект:** VSP Gamer · **Репозиторий:** ValentS1997/vsp-gamer-mods · **Ветка:** main.  
**Источники:** выведенные пользователем команды Debian/Docker/BepInEx, пользовательские игровые тесты, YAML-handoff от PVE-LAB/Stage003.OpenWrt. Указанные PASS не означают выполнение непроведённых тестов.

## 1. Цель и границы

Развернуть отдельный Linux Valheim Dedicated Server для совместного прохождения с модпаком VSP Gamer, перенести существующий мир `Valheim`, обеспечить LAN и публичное подключение через `valheim.vsp-corp.ru:2456`, самостоятельный запуск после reboot, обмен файлами Samba и удалённое хранилище SMB. Разработка VSP Sleep и P2P-сборка ПК — отдельные проекты. Факт наличия DLL на сервере не означает, что такой же DLL требуется каждому клиенту; серверную совместимость проверять по runtime-логам и игре.

## 3. Docker и файловая схема

```text
/srv/valheim/
├── compose/
│   ├── compose.yaml                  # активная конфигурация
│   ├── valheim.env                  # старый env, НЕ источник текущего пароля
│   └── secrets/server_pass          # секрет Valheim, не сохранять в Git
├── config/
│   ├── worlds_local/
│   │   ├── Valheim/                # перенесённый игровой мир, активное имя в Compose
│   │   └── VSP_DS_TEST/            # сохранённый тестовый мир
│   ├── bepinex/
│   │   ├── plugins/                # скопированные серверные DLL
│   │   └── ...                     # конфигурации и прочие данные BepInEx
│   └── backups/                    # локальные ZIP-резервные копии образа
├── server-data/                    # persistent /opt/valheim внутри контейнера
├── share/                          # staging, исходники импорта; Samba valheim-share
│   ├── worlds_local/Valheim/
│   └── BepInExPack_Valheim/BepInEx/
└── rollback/
    └── pre-migration-20261101-110140/
        └── pre-migration.tar.gz    # снимок compose и config до переноса
```

Подтверждённые bind mounts: `/srv/valheim/config:/config` и `/srv/valheim/server-data:/opt/valheim`. Game UDP публикуются адресно: `10.97.1.20:2456:2456/udp` и `10.97.1.20:2457:2457/udp`; порт 2458 не опубликован. В `docker ps` дополнительно отображаются НЕ опубликованные container ports `80/tcp` и `9001/tcp`.

После миграции `WORLD_NAME: "Valheim"`, `SERVER_NAME: "VSP Valheim"`; password читается через `SERVER_PASS_FILE=/run/secrets/server_pass`, bind-mounted из `/srv/valheim/compose/secrets/server_pass` (только чтение). Секрет вводился локально интерактивно; его значение неизвестно документации. `valheim.env` оставлен на диске как исторический конфигурационный файл; актуальный Compose больше не использует `env_file`. Полный итоговый Compose не выгружен как контрольный артефакт; при расхождении проверять сервер.

На проверке после reboot `docker ps` показывал `valheim-server Up` и UDP binds. Docker Engine активен. Compose/образ запускает собственные `valheim-server`, `valheim-updater`, `valheim-backup` через supervisord. В раннем логе сразу после `up -d` игровой процесс ещё имел статус `STOPPED Not started`: это была стадия bootstrap; позднейшие логи и успешное подключение подтвердили запуск. Настройки auto-update в runtime отдельно не аудированы.

## 4. Исходные данные и миграция мира

Из SMB-стейджинга `/srv/valheim/share/worlds_local/Valheim` обнаружены около **20 MiB** данных нового chunk-формата: `_main.398.db2`, `_main.398.fwl2`, `_main.398.chunks`, `_main.398.ok`, файлы `*.chunk` и cacheMinimap*. Номер `398` в имени — номер ревизии сохранения, не версия Valheim.

До импорта активным был созданный сервером тестовый мир `VSP_DS_TEST`, который также сохранялся и резервировался. Миграционный скрипт:
1. проверил файловую систему `/srv/valheim`, исходный мир, число DLL, отсутствие конфликтующего `config/worlds_local/Valheim`;
2. запросил новый пароль дважды без эха;
3. выполнил `docker compose stop -t 120 valheim`;
4. сохранил pre-migration rollback archive;
5. скопировал `worlds_local/Valheim` в `config/worlds_local/Valheim` без удаления оригинала;
6. скопировал `BepInEx/plugins` в `config/bepinex/plugins`, а конфиги — в `config/bepinex` с исключением корневого `BepInEx.cfg*`;
7. изменил Compose на мир `Valheim`, секрет-файл, затем выполнил `docker compose config -q` и `docker compose up -d`.

Вывод завершился `DEPLOYMENT COMMAND COMPLETED`: 43 DLL скопированы, контейнер создан и запущен. **Важное ограничение:** мир загружен и владелец подключился; отдельный inventory всех построек, предметов, модовых объектов, integrity-restore из архива и длительный тест с несколькими игроками не проводились.

## 7. CIFS клиент и инцидент подключения к PVE NET SMB

Удалённая шара `//10.97.253.10/pve-net-smb` монтируется в `/mnt/pve-net-smb` через `cifs-utils`, `/etc/fstab`, опции `credentials=/etc/samba/credentials/pve-net-smb`, `_netdev,nofail,x-systemd.automount`, `uid=1000,gid=1000`, `file_mode=0600,dir_mode=0700`. Учётные данные лежат в **root-only 0600** file, домен `WORKGROUP`.

**Инцидент VSP-VALHEIM-SMB-20261101:**
- До изменения OpenWrt TCP 445 возвращал `Connection refused`, kernel CIFS `error(111)`; в ACL `firewall.prowrt_smb_lab` разрешался только `10.97.1.2/32`.
- Сетевая команда расширила source до `10.97.1.0/24`. TCP 445 стал доступен; это отдельный security tradeoff.
- Затем CIFS дал `STATUS_LOGON_FAILURE (0xc000006d)`/`error(13)`. Ручной `smbclient -U vspadmin` с интерактивным вводом проходил, а `smbclient -A` с сохранённым файлом — нет.
- Credentials-файл был заново создан и протестирован через `smbclient -A` **до** замены оригинала. После этого `ls /mnt/pve-net-smb` и `findmnt -t cifs` вернули PASS, negotiated SMB `3.1.1`.
- Создание/чтение/удаление временного файла на шаре: **PASS**.
- После reboot: systemd automount unit `generated/active`; обращение `ls` инициировало CIFS, `findmnt` показал `rw,vers=3.1.1`; persistent mount **PASS за один reboot**.

Каталоги remote SMB: `PrOWRT`, `dump`, `lost+found`, `template`. Наличие SMB доступа **не равно** внедрённому внешнему backup. Пароль CIFS, старые/новые credentials и приватные ключи в Git не сохранять.

## 8. Внутренняя и публичная сеть

**HOME → LAB:** клиент пользователем был подключён с другой VLAN. Сетевая заявка `VSP-VALHEIM-NET-20261101-001` закрыта `COMPLETED_NO_CHANGE_REQUIRED`: уже существовало широкое правило `firewall.prowrt_home_to_lab_initial` / `Allow-HOME-to-LAB-Initial`, разрешающее все IPv4-протоколы из `10.97.0.0/24` в `10.97.1.0/24`. Маршрут в `lab0`, gateway `10.97.1.1`, PASS от владельца; точный игровой ingress path packet-trace не получен. Широкий allow-all — **открытый security debt**, менять только отдельной заявкой.

**WAN:** заявка `VSP-VALHEIM-WAN-20261101-001` выполнена Stage003.OpenWrt, результат `PASS_OWNER_CONFIRMED`:
- OpenWrt `wan0`: `92.255.183.46/23`, gateway `92.255.183.254`; CGNAT на WAN интерфейсе не обнаружен;
- `valheim.vsp-corp.ru` CNAME → `edge.vsp-corp.ru`, IPv4 `92.255.183.46`, проверен resolver `1.1.1.1`;
- nft/fw4 UCI redirect `firewall.prowrt_valheim_wan` / `Valheim-WAN-UDP`: WAN UDP 2456–2457 DNAT → `10.97.1.20` UDP 2456–2457, `nat_reflection=false`;
- UCI rule, nft DSTNAT/forward accept, `fw4 check`, reload — PASS; DNAT counter изменился с 0 до 2 пакетов/593 bytes при внешней попытке;
- подключение с внешнего клиента к `valheim.vsp-corp.ru:2456` подтверждено владельцем;
- backup конфигурации на OpenWrt: `/root/firewall-before-valheim-wan-20261101-175257`; новые правила **не** открывают TCP SSH/SMB/Docker API.

Не сделаны: повторный внутренний LAN-тест после DNAT, отрицательные внешние проверки TCP 22/445 и иных портов, фиксация IPv4 внешнего клиента. DNAT включён; публичный endpoint реально доступен.

## 9. UFW / Docker firewall

UFW `0.36.2-9` установлен на Debian 13; состояние `ufw status verbose` **active**, defaults `deny incoming / allow outgoing / deny routed`, logging low. В runtime разрешены:
- SSH TCP 22 → `10.97.1.20` только с `10.97.0.10` и `10.97.1.0/24`;
- Samba TCP 445 → `10.97.1.20` из `10.97.0.0/24` и `10.97.1.0/24`;
- отдельного host UFW allow для Valheim не добавляли; публикация Docker идёт через FORWARD/NAT.

`ufw.service`: `is-enabled=enabled`, `/etc/ufw/ufw.conf: ENABLED=yes`, но **в текущей загрузке** systemd `Type=oneshot, RemainAfterExit=yes, ActiveState=inactive/SubState=dead`; `ufw status` при этом active. Проверка фактического восстановления firewall **после нового reboot** остаётся PENDING; не путать с выполненной проверкой перезагрузки CIFS до установки UFW.

Docker: `iptables v1.8.11 (nf_tables)`, `dockerd -H fd://...`, `FORWARD` начинается с перехода в `DOCKER-USER` (пустая цепочка), далее `DOCKER-FORWARD`. DNAT перенаправляет `10.97.1.20:2456/udp` → `172.18.0.2:2456`, аналогично 2457. На момент аудита UFW и Docker работают параллельно. Ограничение контейнера только публикацией UDP 2456–2457 **не эквивалентно** отдельному явному фильтру `DOCKER-USER` по источнику; межзональную политику обеспечивает OpenWrt. Ручное изменение nft-таблиц Docker запрещено.
